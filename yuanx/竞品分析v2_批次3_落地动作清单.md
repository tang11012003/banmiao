### P0-2 ▸ 诊断报告→社区分享路径（内容飞轮开关）

| 项 | 内容 |
|---|---|
| **涉及文件** | `fenxibaogao.html` → `fabutiezi.html` → `shequ.html` |
| **来源结论** | 批次 1：所有 12 家竞品中没有一家实现"诊断→报告→社区分享"闭环，这是 yuanx 独有的结构性机会 |
| **当前状态** | `fabutiezi.html` 已支持嵌入诊断报告卡片 ✅，但 `fenxibaogao.html` 无"分享到社区"入口 ❌ |
| **具体动作** | |

1. **`fenxibaogao.html` 报告页底部增加两个按钮**：
   - 「分享到社区」→ 跳转 `fabutiezi.html`，自动填充模板帖：
     > "[数学] 二次函数最值题，连错 3 次后我找到了这个规律..."
     > + 报告截图卡片（自动脱敏：隐去孩子姓名，保留知识点标签）
   - 「生成分享图」→ 生成一张朋友圈/小红书可发的诊断报告卡片图

2. **脱敏规则**：
   - 隐去：孩子姓名、学校名、具体分数
   - 保留：科目、知识点标签（"二次函数·最值"）、错因类型（"概念混淆"）、掌握度等级
   - 让分享帖有信息量但不泄露隐私

| **预期效果** | 打通 fenxibaogao → shequ 的内容飞轮，每份诊断报告都可能变成一条社区帖子，每条社区帖子都可能带来一个新用户 |
|---|---|
| **工作量估算** | 前端中等（模板帖生成 + 卡片图生成） |
| **风险如不做** | 🔴 诊断和社区两个功能各自孤立，社区沦为纯 UGC（家长100 的老路），诊断报告只是"看完就走"的一次性内容 |

### P0-4 ▸ 错题数据结构必须支持跨期积累

| 项 | 内容 |
|---|---|
| **涉及文件** | `cuoti.html` · `changqifenxixq.html` |
| **来源结论** | 批次 1：yuanx 的护城河不在 AI 模型，在"孩子的历史试卷 + 跨期错题记录"的时间壁垒。用户使用 6 个月后数据迁移成本极高 = 天然续费动力 |
| **当前状态** | `cuoti.html` 已有按科目展示错题统计和历次复盘记录 ✅；`changqifenxixq.html` 已有成长趋势分析 ✅ |
| **具体动作** | |

1. **确认数据结构**（后端/数据层）：
   - 每条错题记录必须包含：考试日期、科目、知识点标签、错因类型、是否已掌握
   - 同一知识点的错题必须能跨考试关联（"二次函数·最值"在 3 月月考错了 → 4 月期中又错了 → 5 月模考对了）
   - `changqifenxixq.html` 的趋势图数据源必须是跨期聚合的，不能是每次独立报告

2. **`cuoti.html` 增加"知识点掌握轨迹"视图**：
   - 除了按科目/按考试筛选，增加"按知识点"维度：列出所有曾错过的知识点，每个知识点展示"错→错→对"的时间线

| **预期效果** | 6 个月后家长看到孩子从"二次函数连错 3 次"到"终于掌握"的完整轨迹，这是不可替代的数据资产 |
|---|---|
| **工作量估算** | 数据结构设计高优，前端展示中等 |
| **风险如不做** | 🔴 如果每次诊断是独立的，用户随时可以换产品，零迁移成本 = 零护城河 |
